# M3.0 技术验证：用户态协议栈 + Linux 虚拟网卡

`cargo run --release`（需要 CAP_NET_ADMIN）：建虚拟网卡 nxprobe0（10.77.0.1/24，不用 ip 命令，tun-rs 自己配地址），
用 ipstack 1.0 在网卡上接住内核发来的 TCP 连接；内核里的程序连 10.77.0.2。

2026-11-16，开发容器（2 核）：

| 项 | 结果 |
| --- | --- |
| 往返延迟（4 字节回声） | p50 50 µs，p99 138 µs |
| 单连接吞吐 | 109 MiB/s（协议栈一侧只计数） |

结论：

- ipstack 可用。它要一个「每次读写是一个 IP 包」的设备，这正好是我们要的接缝：真实环境接虚拟网卡，
  仿真里接内存管道，所以统一入口的引擎可以在仿真里测。
- 虚拟网卡的地址和路由不需要 ip 命令；更复杂的路由（例如只把 fd00::/8 指进来）再用 netlink。
- iroh 的发送流支持优先级（noq `SendStream::set_priority`），满载调度的测量放在 M3.5（需要限速的链路）。
- Android 交叉编译放到 M3.6（需要 NDK）。
