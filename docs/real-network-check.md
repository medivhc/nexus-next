# 两台真实设备上的验证

目的：确认在真实网络（包括国内网络）上，两台不在同一局域网的设备能否互通、走直连还是中继、上手要多久。
自动化测试只覆盖了同一台机器上的进程（只用回环地址），这一步必须在真实设备上做。

## 准备

- 设备 A：例如家里的电脑。设备 B：例如公司电脑、手机热点下的笔记本，或一台 VPS。两者不在同一个局域网。
- 两台都装好 `nexus`（`cargo build --release`，二进制在 `target/release/nexus`）。
- 准备一个计时器，记录每一步的耗时。

## 步骤

| 步 | 在哪台 | 命令 | 记录 |
|---|---|---|---|
| 1 | A、B | `nexus daemon &` | 是否有报错 |
| 2 | A | `nexus init --name a` | |
| 3 | B | `nexus join` | 是否给出短加入码（经公共的碰头服务） |
| 4 | A | `nexus device approve <短加入码> --name b`（不行时用长码） | 是否成功、耗时；短码报错时记下原因 |
| 5 | A | `nexus status b --json` | `online`、`path`（direct / relay）、`rtt_ms` |
| 6 | A | `nexus ssh b`，输入几条命令，Ctrl-] 断开再连上 | 体感延迟、屏幕是否恢复 |
| 7 | A | `nexus exec b --json -- uname -a` | 耗时 |
| 8 | A | 等 1 分钟后再执行第 5 步 | 路径是否从中继升级为直连 |
| 9 | A | 断开 B 的网络 30 秒再恢复，期间开着 `nexus ssh b` | 是否自动恢复 |

从第 2 步开始到第 6 步第一次出现提示符的总耗时，就是跨网络的上手成本（需求 R27）。

## 结果怎么判断

- **第 4 步失败或很慢**：iroh 的公共中继或地址发现在这个网络里不可达。改用自己的中继：
  最省事的是在一台两边都能访问的 VPS 上部署锚点（`docs/anchor.md`），它就是中继；还没加入网络时，
  两台设备先都用 `nexus daemon --relay https://<锚点域名>` 启动。也可以运行 iroh 的 `iroh-relay`，
  同样用 `--relay` 指定。如果地址发现也不可达，再加 `--no-discovery`
  （加入码里已经带着地址提示，批准和名册推送也会传递地址）。
- **一直是 relay**：两边都在对称 NAT 后面，打洞失败。能用，但延迟取决于中继的位置；自建中继放在离两边都近的地方。
  `nexus path b` 列出每条路径（本机地址、对方地址、直连还是中继、往返时间），可以看到具体走了哪条。
- **B 有两个网络（例如 Wi-Fi 和手机热点）**：`nexus path b` 应该有两条直连路径；在 B 上断开其中一个网络，
  `nexus ssh b` 的会话不应该断（手册第 15 节）。
- **第 9 步没有恢复**：把 `nexus daemon` 的输出和两边的 `nexus audit --json` 一起记下来。

## Android 单 VPN 异网验收（#43）

记录构建提交、手机型号和 Android 版本、家庭节点和 VPS 的系统版本，以及各设备所用网络。家中节点 `home` 发布私有 TCP 和 UDP 服务，VPS 开放 `nexus exit on`。手机分别在 Wi-Fi 和蜂窝上使用同一个 VPN 配置完成下列检查。

| 场景 | 记录 |
| --- | --- |
| 指定一个 App 强制使用 VPS，另一个 App 设置绕过 | 分别记录公网 IPv4、IPv6 的出口地址，并用受控目标验证指定应用的 TCP、UDP 及绕过应用的直连 |
| 在保留公网 TCP 和 UDP 活动时访问 `home` | 记录 `.internal` 的 DNS 结果及私有 TCP 和 UDP 的往返结果 |
| 关闭 VPS 出口，或选择拒绝 `UDP ASSOCIATE` 的 SOCKS5 | 记录手机上的失败原因，使用目标端的日志确认没有收到未经授权的直连 |
| 用可记录查询的 DNS 服务验证私有域名 | 确认 VPN 内普通 UDP/TCP DNS 的 `.internal` 请求未到外部，分别记录系统私有 DNS 与应用自行使用加密 DNS 的行为 |
| Wi-Fi → 蜂窝 → Wi-Fi 及息屏后唤醒 | 记录现有连接的恢复时间、新连接的结果、`nexus path` 输出及失败日志 |
| 停用 VPN | 记录原系统 DNS 和网络路由的恢复情况 |
| 分别运行常开和按需蜂窝备用链路 | 在同一手机、同等负载和相同时间窗口下记录耗电、恢复时间、后台稳定性及空闲时是否释放蜂窝请求 |
