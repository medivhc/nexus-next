# 路线：阶段 6 之后

依据：产品文档 v0.4（第 11 节可靠性、第 15 节路线「之后」）、手册第 19 节「已知限制」。2026-11-21 整理，2026-11-25 更新现状。

## 现状

阶段 0–5 完成（R01–R61），阶段 6 完成两项易用性改进：短加入码（R62、R63）、恢复管理设备（R64）。
2026-11-25：阶段 7 除 M7.0 外完成（R65–R69），阶段 8、9 完成（R70–R74），下面的差距表里只剩第一行和最后一行的远程桌面。
所有测试都在同一台机器上（回环地址、网络命名空间、仿真）。

和产品文档对照，差距按影响排序：

| 差距 | 产品文档 | 现状 |
| --- | --- | --- |
| 没有在真实的跨网络设备上用过 | 第 13 节「上手」「连接」指标 | 只有 `docs/real-network-check.md` 的清单 |
| 升级要所有设备一起换 | 11：「不同时升级所有节点，相邻版本必须能互通」 | 每次协议变化 wire 版本 +1，版本不同就拒绝 |
| 常驻程序重启，终端会话就没了 | 7.1：会话由独立的持有进程管理；11：「升级不中断终端会话」 | 会话在常驻程序进程里 |
| 没有升级和回滚 | 11：「升级失败自动回滚」 | 手动换二进制 |
| 网页节点只有终端 | 7.3：文件浏览、打开已发布的网页服务 | 终端和状态 |
| 没有 `nexus open` | 4.1：`nexus open home/web` | 要 `connect --listen` 再开浏览器 |
| 临时分享、凭据、硬件能力、远程桌面 | 7.4、7.5、9 | 都没做 |

## 阶段 7：日常可用（先做）

目标：能把自己的几台设备长期跑在上面，升级不打断工作。产品文档的保留意见第 1 条：「靠每天自己使用来决定后面做什么」，
这一阶段是每天使用的前提。

| 编号 | 交付 | 完成时能演示的 |
| --- | --- | --- |
| M7.0 | 真实网络验证（需要两台不同网络的设备，用户配合） | 按清单在家里和公司/手机热点之间走一遍，记录直连/中继、上手时间、断网恢复；发现的问题进 M7.x |
| M7.1（完成） | 相邻版本互通 | 一台设备升级到新版本，另一台还是旧版本，`ls`、`ssh`、`exec`、`drive sync` 照常；旧版本遇到不认识的请求明确报「对方版本较新，这项功能要升级」而不是断开 |
| M7.2（完成） | 终端会话在常驻程序重启后保留 | 会话由独立的持有进程管理；`nexus ssh home` 里跑着 `top`，home 上重启常驻程序，客户端几秒内自动接回，屏幕内容还在 |
| M7.3（完成） | 升级与回滚 | `nexus upgrade --file` 校验、替换、重启（下载交给浏览器或 curl：仓库是私有的）；新版本限定时间内连不上网络就退回上一版；会话不断（依赖 M7.2） |
| M7.3b（完成） | 推给其他设备 | `nexus upgrade --to home`（或 `--all`）：本机把新版本经 Nexus 推给同平台的设备，各自检查、替换、确认；不需要每台设备都能下载 |
| M7.4（完成） | `nexus open` | `nexus open home/web` 在本机浏览器里打开发布的网页服务（自动开端口、按服务说明拼地址） |

M7.1 要先定下兼容规则：请求和回应带能力列表或可忽略的扩展字段，加新请求不改 wire 版本；
只有改变已有消息含义时才升主版本，并且新版本仍能和上一个主版本通信。之后每个里程碑都要过「新旧版本混跑」的场景。

## 网络运行时：日常替代与省电（N0–N2）

设计见 `docs/design/network-runtime-n0-n2.md`，功能点见 `docs/feature-points/N1.md`、`N2.md`，测试用例见 `docs/test-cases/network-runtime-n0-n2-test-cases.md`。
目标是让 Android 上的 Nexus 能替代日常用的 Clash / EasyTier，并且不再因为一直保持蜂窝网络而耗电。

| 编号 | 交付 |
| --- | --- |
| N0（完成） | 对照现有代码核实差距（路由、出口、完整节点、Android 单 VPN、多路径） |
| N1（完成） | 精确域名规则与规则审计（R100）、Clash / Mihomo 规则导入与回滚（R101）、经出口转发公网 UDP（R102，协议 19.6）、Android 按应用绕过（R103） |
| N2（完成） | Android 电源模式，默认不保持蜂窝网络，一键停止（R104）；耗电对比待真机实测 |

## 建议的顺序

M7.0 和 M7.1 并行：M7.0 要用户的设备和时间，M7.1 不需要。M7.1 之后的每次升级都不用再「所有设备一起换」，
所以它应当在发布 0.1.0 之后、任何人开始长期使用之前完成。
