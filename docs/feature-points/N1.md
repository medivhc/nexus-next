# N1 功能点与验收标准：Android 日常替代最小集

对应 RFC v0.1 阶段 **N1**（覆盖用户场景 U01、U02、U06、U07 基础及 U12 规则导入/回退），在基线 `d85380d` 上补齐日常可用最小闭环。

## 验收门禁（硬性红线）

1. **L0 静态门禁全绿**：`python3 tools/check.py` 与 `--self-test` 全部通过（纯逻辑层零系统依赖、零 `unsafe`、需求追溯与许可证无违规）。
2. **零非授权直连泄露**：`Reject` 规则、暂不支持 UDP 的 `Socks5` 上游、以及导入中未映射的节点组，均不得静默降级为直连。
3. **零出口本机地址访问**：`ExitDatagram` 严格拒绝连接出口设备的 `127.0.0.0/8`、`::1`、`0.0.0.0`、`::`。
4. **零 VPN 环路**：Android 应用绕过列表无论如何配置，自身包名 `link.bewith.nexus` 必须始终处于 `disallowed_packages`。
5. **诚实标注环境**：redroid 验证结果明确标注为模拟器/容器环境，真机项未跑则标 `BLOCKED（待真机执行）`，绝不把 redroid 报告成真机。

## FP-N1-01 精确域名匹配（`DomainExact`）与后缀匹配（`Domain`）隔离
- **Given** 路由表包含 `DomainExact("api.example.com") -> Exit("jp")` 与 `Domain("example.com") -> Direct`
- **When** 请求目标为 `api.example.com:443`
- **Then** 命中 `DomainExact` 规则，走 `Exit("jp")`
- **When** 请求目标为 `sub.api.example.com:443` 或 `www.example.com:443`
- **Then** 不命中 `DomainExact`，命中 `Domain("example.com")` 走 `Direct`

## FP-N1-02 规则静态审计（冲突、遮蔽与无效上游检测）
- **Given** 规则列表包含：
  1. `Domain("example.com") -> Direct`
  2. `DomainExact("api.example.com") -> Exit("jp")`（被第 1 条遮蔽）
  3. `Domain("example.com") -> Reject`（与第 1 条重复）
  4. `Domain("bad.test") -> Socks5("not-a-valid-addr")`（无效上游）
- **When** 执行 `route::audit_rules` 或 `nexus route audit`
- **Then** 审计报告明确指出第 2 条被第 1 条遮蔽、第 3 条重复、第 4 条上游地址非法，且无误报

## FP-N1-03 Clash / Mihomo 规则子集可审计导入
- **Given** 一份包含 `DOMAIN`、`DOMAIN-SUFFIX`、`IP-CIDR`、`IP-CIDR6`、`MATCH` 以及不支持项（`GEOIP`、`SCRIPT`、`MITM`、`PROCESS-NAME`）的 Clash YAML 规则片段
- **When** 执行 `parse_clash_rules` 或 `nexus route import <file> --via jp-exit --dry-run`
- **Then** 合法规则按预期转换为 `DomainExact` / `Domain` / `Cidr`；所有不支持项和未映射策略均被跳过并在报告中列出原因；绝不自动启用脚本或 MITM，绝不把未映射的代理组静默改为 `Direct`

## FP-N1-04 规则原子导入与 LKG 一键回滚
- **Given** 节点当前生效 1 条既有规则 `R_old`
- **When** 通过 `CtlRequest::RouteImport { replace: true }`（或 `nexus route import --replace`）导入新规则集 `R_new`
- **Then** 新规则立即生效，且既有规则 `R_old` 自动保存为 Last-Known-Good（`routes_lkg`）快照
- **When** 执行 `CtlRequest::RouteRollback`（或 `nexus route rollback`）
- **Then** 节点规则原子恢复为 `R_old`，后续 `route explain` 与转发行为与导入前完全一致

## FP-N1-05 通用公网 UDP 经出口节点转发（`Request::ExitDatagram`）
- **Given** 设备 `home` 已执行 `nexus exit on` 开启出口，并在非回环地址运行一个 UDP 回声目标；设备 `phone` 配置规则 `Domain("udp.far.test") -> Exit("home")`
- **When** `phone` 经完整节点/TUN 向 `udp.far.test` 的 FakeIP 发送 UDP 数据报
- **Then** 数据报经 `Request::ExitDatagram` 到达 `home`，由 `home` 转发到目标并将回应原路送回 `phone`；`home` 审计日志记录 `net.exit`

## FP-N1-06 UDP 出口安全底线：禁止本机地址 & 不支持时绝不偷偷直连
- **Given** 设备 `home` 开启出口，设备 `phone` 配置 `Domain("local.test") -> Exit("home")`（其中 `local.test` 在 `home` 上解析为 `127.0.0.1`）以及 `Domain("socks.test") -> Socks5("127.0.0.1:7890")`
- **When** `phone` 向 `local.test` 发送 UDP 数据报
- **Then** `home` 拒绝该请求（`ErrorCode::Denied`），不转发至 `home` 本机 `127.0.0.1`
- **When** `phone` 向 `socks.test`（上游 SOCKS5 暂不支持 UDP）或 `Reject` 域名发送 UDP 数据报
- **Then** 数据报被明确丢弃，绝不降级直连发出

## FP-N1-07 Android 应用绕过 VPN 与防环路保护
- **Given** 用户配置绕过 VPN 的应用包名列表（含合法包名、重复项、空白或恶意删除自身包名）
- **When** 经 `AppPolicy::effective_disallowed_packages("link.bewith.nexus")` 归一化并交由 `NexusVpnService` 应用
- **Then** 返回去重后的合法包名列表，且强制包含 `link.bewith.nexus`；被排除应用的流量不进入 TUN，不触发 VPN 环路

## FP-N1-08 Android 单 VPN 构建与 UI 操作闭环（redroid 实测 + 真机清单）
- **Given** 通过 `tools/build-android.sh x86_64` 构建 `target/android/nexus.apk`
- **When** 安装到 redroid (`Android 14`, `x86_64`) 并启动 `MainActivity`
- **Then** 应用无崩溃启动，正确完成 VPN 授权与核心拉起；已加入界面展示状态、电源模式切换和「停止 VPN」按钮，点击「停止 VPN」后服务与 TUN 立即释放
- **And** 真机验收项（arm64-v8a、异网、真实 Clash 订阅）保留明确的手工执行步骤并标注 `BLOCKED（待真机执行）`
