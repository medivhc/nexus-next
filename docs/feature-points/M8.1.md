# M8.1 功能点：网页里浏览工作区

## 模型

- 工作区的内容按提交保存在存储设备上（`nexus drive serve on` 的设备，R50）。网页节点和其他设备一样，
  向存储设备要工作区的头和对象（目录、文件清单、块），在浏览器里拼出目录和文件；每个对象按哈希校验。
- 网页节点核心（浏览器和测试里是同一份代码）提供三个操作：
  - **列出工作区**：问每台能看到的设备有没有开 serve、上面有哪些它能读的工作区。同名的工作区在多台存储设备上时取名字靠前的设备。
  - **列出目录** `<工作区>` + 路径：每一项的名字、种类（`file`、`dir`、`symlink`）、文件大小、链接的目标；目录在前，按名字排序。
  - **读文件** `<工作区>` + 路径 + 最多读多少：返回文件的总大小和开头的那么多字节（`truncated` 表示没读完）。
    页面预览时最多读 1 MiB；下载时读整个文件，存成浏览器里的下载。
- 错误：工作区不在任何能看到的存储设备上，或路径不存在：`NotFound`；对文件列目录、对目录读文件：`InvalidInput`；
  没有 `drive.read@<存储设备>/drive/<工作区>`：`Denied`（存储设备判定，审计里记录）。工作区还没有提交：目录是空的。
- 页面：设备列表下面多一栏「工作区」。点开工作区按目录浏览，路径可以返回上一级；文件点开后：
  文本（UTF-8，不含 NUL）显示内容，图片（png、jpeg、gif、webp、svg 按扩展名）显示图片，其他显示大小；
  每个文件都有「下载」。没有能读的工作区时说明怎样授权（`--grant drive.read@**`）。
- 默认的网页授权（终端会话、状态）不变，不含 `drive.read`。

## FP-8.1-01 列出工作区和目录（R70）
- Given laptop 建立网络，anchor 开了 serve，laptop 的工作区 work 有 `a.txt`、`src/b.rs`、`logo.png` 并已提交
- And 通行密钥 phone 登记时授权 `node.info@**`、`drive.read@**`
- When 浏览器用 phone 登录，列出工作区
- Then 有 work（在 anchor 上）
- And 列 work 的根：`src`（目录）在前，然后 `a.txt`（5 字节）、`logo.png`；列 `src`：`b.rs`

## FP-8.1-02 读文件（R70）
- 读 `src/b.rs`：内容和提交的逐字节相同，`truncated` 为假
- 一个 3 MiB 的文件最多读 1 MiB：返回开头 1 MiB，总大小 3 MiB，`truncated` 为真；读整个文件：逐字节相同
- anchor 的审计里有主体为 phone 的 `drive.read` 记录

## FP-8.1-03 不存在和没有授权（R70）
- 不存在的工作区、不存在的路径：`NotFound`；对 `a.txt` 列目录：`InvalidInput`；对 `src` 读文件：`InvalidInput`
- 只有默认授权的通行密钥：列出的工作区是空的；直接读 `work` 的文件：`Denied`
- 只授权了 `drive.read@anchor/drive/docs` 的通行密钥：只看到 docs，看不到 work

## FP-8.1-04 看到的是同步了的提交（R70）
- laptop 改了 `a.txt` 还没提交：页面里还是原来的内容；提交（同步到 anchor）之后：页面里是新的内容
