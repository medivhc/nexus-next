# M1.3 功能点：结构化执行

命令不经过 shell：`nexus exec home -- 程序 参数...` 直接启动程序。需要 shell 特性时显式写 `sh -c '...'`。

## FP-1.3-01 拿到输出和退出码（R09）
- Given 网络里的 home
- When `nexus exec home -- sh -c 'echo out; echo err >&2; exit 3'`
- Then 标准输出是 `out`，标准错误是 `err`，退出码是 3
- And 加 `--json` 时得到一份 JSON：退出码、标准输出、标准错误、耗时、是否超时、是否截断

## FP-1.3-02 标准输入是流式的（R09）
- When 把一段输入通过管道交给 `nexus exec home -- cat`
- Then 远端的 `cat` 收到完整的输入并原样输出；输入结束后命令正常退出

## FP-1.3-03 输出可以是任意字节（R09）
- When 远端命令输出不是合法 UTF-8 的字节
- Then 直接输出时字节原样到达；`--json` 时以 base64 给出

## FP-1.3-04 大量输出完整送达（R09）
- When 远端命令输出几 MB 数据
- Then 全部送达，一个字节不少

## FP-1.3-05 工作目录与环境变量（R09）
- When `nexus exec home --cwd /tmp --env FOO=bar -- sh -c 'pwd; printenv FOO'`
- Then 输出 `/tmp` 和 `bar`

## FP-1.3-06 超时如实标记（R10）
- When `nexus exec home --timeout 1 -- sleep 30`
- Then 大约 1 秒后命令被终止，退出码 124；`--json` 中 `timed_out` 为真、没有退出码

## FP-1.3-07 输出超限如实标记（R10）
- When `nexus exec home --max-output 1000 -- head -c 100000 /dev/zero`
- Then 恰好收到 1000 字节，命令被终止，退出码 125；`--json` 中 `truncated` 为真

## FP-1.3-08 命令不存在是明确的错误（R10）
- When `nexus exec home -- no-such-program`
- Then 退出码 127，标准错误是一行结构化的原因

## FP-1.3-09 也能在本机执行，名字不对时明确报错（R09）
- When 在 laptop 上 `nexus exec laptop -- echo hi`
- Then 正常执行
- When 目标是名册里没有的节点
- Then 退出码 103
