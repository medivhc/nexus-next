# M12.1 功能点：跨设备随需审批（Just-in-Time Approval）

## 模型

- 在现有二元授权（`allow` / `deny`）之间引入第三态 **`ask`（需本人即时批准）**，使 agent 对高危能力（如 `term.exec`、`drive.write`、`vault.read`、`term.session.kill`）默认保持零常驻特权。
- 向后兼容编码：`--ask 能力@资源` 在 `AgentCert.grants` 中以 `ask.<能力模式>` 编码（例如 `ask.term.exec@home`），完全不改变 `AgentCert` 签名格式与 19.0–19.5 线上编码；旧版本节点收到时按不匹配自动拒绝（Fail-Closed）。
- 协议次版本升至 `19.6`，新增 `Request::ApprovalList`、`Request::ApprovalDecide`、`Request::ApprovalRevokeGrants`、`Request::ExecWithReason`，对应回应 `Response::Approvals`、`Response::ApprovalDecided`、`Response::ApprovalGrantsRevoked`，以及错误码 `ErrorCode::ApprovalDenied`、`ErrorCode::ApprovalTimeout`、`ErrorCode::NoApproverOnline`。
- 审批簿（`nexus-core-proto::approval::ApprovalBook`）是纯逻辑确定性状态机：不碰系统时间、IO 或随机数；内存临时提权缓存不落盘，重启或撤销 agent 后立即失效。
- 安全边界：agent 凭据严禁访问任何审批接口（无论是否持有通配授权），违规尝试写入目标设备 `nexus audit`；管理设备与本机默认具备审批权，其他成员设备需在目标设备上显式执行 `nexus device set-approver <设备> on`。

## FP-12.1-01 `ask` 授权挂起、单次放行与重复裁决冲突（R93、R94）
- Given 为 agent 签发 `--ask term.exec@home` 凭据
- When agent 执行 `nexus exec home --reason "检查版本" -- echo ok`，`laptop` 查询 `nexus approval ls --json` 并执行 `nexus approval approve <id>`
- Then 审批单包含完整 `reason` 与操作摘要；放行后 agent 命令成功返回 `ok`；随后若再次对同一 `<id>` 执行 `nexus approval deny <id>`，返回状态冲突（退出码 `106`）

## FP-12.1-02 审批超时默认拒绝并记入审计（R93、R97）
- Given `home` 通过 `nexus approval timeout 1s` 设定超时，agent 发起 `ask` 级别的 `exec`
- When 超时窗口内无人裁决
- Then agent 收到退出码 `105` 与结构化错误 `approval_timeout`，`home` 的 `nexus audit --json` 记录 `ask` 与 `approval_timeout`

## FP-12.1-03 临时提权（TTL）与撤销联动（R95）
- Given agent 触发 `ask` 审批，管理设备以 `--ttl 10m` 批准
- When agent 在有效期内再次执行同一能力与资源
- Then 第二次请求直接放行无需再次审批；随后撤销该 agent（`nexus agent revoke`）或执行 `nexus approval revoke-grant`，后续请求立即失效

## FP-12.1-04 MCP 透传 `reason` 与拒绝理由结构化返回（R96）
- Given agent 经 `nexus mcp` 调用 `nexus_exec` 并传入 `reason`
- When 审批人执行 `nexus approval deny <id> --note "先跑单测"`
- Then `nexus mcp` 返回 `isError: true`，且 `structuredContent` 包含 `code: "denied_by_user"` 与 `note: "先跑单测"`

## FP-12.1-05 防自批与成员审批设备授权（R94、R97）
- Given 网络中有管理设备 `laptop`、目标设备 `home`、成员设备 `phone` 与 agent
- When agent 尝试调用 `nexus approval ls` 或 `nexus approval approve`；以及未授权的 `phone` 尝试审批
- Then agent 调用直接返回 `105` 并写入审计；`phone` 在未开启 `set-approver` 前被拒，在 `home` 上执行 `nexus device set-approver phone on` 后可正常查询并批准
