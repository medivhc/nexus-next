# M3.6 功能点：Android

Android 上的 Nexus 是一个应用：界面很薄，常驻程序就是同一份核心（`nexus` 的常驻部分），在应用进程里运行。
入口是系统的 VPN（VpnService）：

- VPN 只接管完整节点的网段（默认 198.18.0.0/16）和名字服务（198.18.0.2）。系统里所有程序的名字查询都到这个名字服务：
  `.internal` 和规则里不直连的域名得到本机临时地址，经 VPN 进入核心；其余名字照常解析，连接不经过 VPN。
- 因此同一个入口同时承载两种流量：访问网络里的服务（内网访问），和规则送去出口设备的流量（出口）。
  不接管的流量照常走手机自己的网络，不受影响。
- Nexus 应用自己的连接不经过自己的 VPN（否则会绕回自己）。
- 控制方式和其他设备一样：`nexus` 命令行经应用数据目录里的控制套接字（测试时经 adb 以 root 运行）。

第一版不做：接管全部流量（默认路由）、UDP、界面上的加入和授权流程（用命令行完成）。

## FP-3.6-01 核心在 Android 上运行（R46）
- `nexus` 为 Android（x86_64 和 aarch64）交叉编译；应用启动 VPN 后，核心作为一台设备加入网络

## FP-3.6-02 同一个入口：内网访问和出口同时可用（R46，实测）
- Given 一台 Linux 设备 home：发布了网页服务 web，开放了出口；还有一个网站 far.test，只有 home 能按名字找到
  （测试里在 home 的 /etc/hosts 里临时加一行，指向本机的一个非回环地址）
- And Android 设备 phone（应用启动了 VPN）加入网络，规则 `--domain far.test --via home`
- When phone 上的普通程序（以 shell 账号运行的 nc，受 VPN 管理）访问 http://web.home.internal/
- Then 拿到 home 上服务的回应
- When 它访问 far.test
- Then 经 home 出去，拿到网站的回应；home 的审计里有 net.exit 的记录
- When 它解析 localhost
- Then 得到 127.0.0.1（其余名字照常解析，连接不经过 Nexus）

## 实测环境与结果

云端机器上的 redroid（Android 13，x86_64，容器和宿主共用网络）。脚本：`tools/android_e2e.py`，
2026-11-18 连续三次全部通过。redroid 里没有 `/dev/tun`（真机由系统建），脚本会补上。

真机（aarch64，`tools/build-android.sh arm64-v8a`）在你的手机上再验一遍。

## 已知限制

- ~~不支持半关闭~~：M11.5 起支持（R89，见 `docs/feature-points/M11.5.md`）。
- Android 会尝试对名字服务用加密 DNS（853 端口）；名字服务只接普通 DNS（UDP 53），系统随后退回普通 DNS。
- 第一版不接管全部流量（默认路由）。UDP 只转发到发布成 `--proto udp` 的服务（M11.5，R91）。
