# M4.4 功能点：预读与衡量

## 模型

- **记录**：`nexus drive record <工作区> [--name <名字>]` 开始记录这台设备读了工作区里的哪些文件（`drive cat`、
  挂载里的读都算），`nexus drive record <工作区> --stop` 结束，得到一份**预读清单**（文件的路径，按第一次读到的顺序）。
  名字默认 `default`。`nexus drive mount ... --record <名字>` 在挂载期间记录，卸载时结束。
- 清单保存在本机，并交给工作区的存储设备，所以别的设备也能用它。同名的清单被新的替换。
- **预读**：`nexus drive prefetch <工作区> [--profile <名字>]` 按清单把文件内容提前取到本机（按清单的顺序；
  已经在本机的不再取；清单里已经不存在的文件跳过）。清单优先用存储设备上的（最新），取不到时用本机的。
  `--all` 取整个工作区的内容（把这台设备变成完整副本，可以离线用）。
- 第一版按整个文件记录和预读（构建读文件几乎都读完整个文件）；按范围记录之后再看是否需要。
- 授权：记录会改变清单，需要 `drive.write`；预读只读，需要 `drive.read`。

## FP-4.4-01 记录预读清单（R54）
- Given work 已复制到 anchor，desktop 同步过 work
- When desktop `drive record work --name build`，读 `a.txt` 和 `src/b.rs` 的一段，再读一次 `a.txt`，然后 `drive record work --stop`
- Then 得到清单 build：两个文件，按第一次读到的顺序（`a.txt`、`src/b.rs`），已交给 anchor
- 没有在记录时 `--stop`：106；工作区不存在：109

## FP-4.4-02 在新设备上预读（R54）
- Given 清单 build 在 anchor 上；tablet 是新设备，同步过 work（只有目录结构）；laptop 和 desktop 都关机了
- When tablet `drive prefetch work --profile build`
- Then 两个文件的内容都在本机（`where` 显示本机 100%），大文件 `big.bin` 没取（本机 0）；报告文件数和取到的字节数
- When 再预读一次
- Then 什么也不用取（取到 0 字节）
- When 清单不存在：109
- When `drive prefetch work --all`
- Then 整个工作区的内容都在本机；anchor 也关机后照样能读 `big.bin`

## FP-4.4-03 挂载时记录（R53、R54）
- Given desktop 挂载 work 时带 `--record build`
- When 程序在挂载里读了几个文件，然后卸载
- Then 清单 build 就是这几个文件；另一台设备能按它预读

## FP-4.4-04 授权（R51、R54）
- 只有 `drive.read` 的 agent 能预读、不能记录（105）

## FP-4.4-05 衡量（R55）
- `tools/drive_bench.py`：两台设备在网络命名空间里，中间是限速、有延迟的链路（默认 100 Mbit/s、往返 20 毫秒）。
  home 导入 nexus-next 的源码并提交；新设备同步、挂载、在挂载里构建，记下：
  - 打开到可用的时间（同步加上挂载，到能 `ls` 和读 `Cargo.toml`）
  - 构建耗时：本地目录、挂载（没有预读，边用边取）、挂载（先按上一台设备记录的清单预读）
  - 预读取了多少字节、多少时间
- 结果写进 `docs/measurements/M4.4.md`。依赖（cargo 的缓存）不经工作区，构建产物放在挂载之外。
