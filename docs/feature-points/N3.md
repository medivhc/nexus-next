# N3 功能点与验收标准：统一策略、DNS 改写过滤与服务诊断

对应 RFC v0.1 阶段 **N3**（覆盖 U03、U04、U07、U09 基础）。

## FP-N3-01 地域硬约束选路与淘汰可解释（U03）
- **Given** 候选出口列表含 `us-1`（US, healthy, 20ms）、`jp-1`（JP, healthy, 80ms）、`jp-2`（JP, healthy, 45ms）
- **When** 策略要求 `region = JP`
- **Then** 确定性选择 `jp-2`（RTT 更优），淘汰报告中 `us-1` 标明地域不匹配
- **When** 所有 `JP` 出口均不健康
- **Then** 即使 `us-1` 健康且 `on_failure = DirectIfAllowed`，仍严格阻断，绝不跨地域漂移或降级直连

## FP-N3-02 固定稳定出口故障阻断与告警（U04）
- **Given** Claude 等账号型服务配置 `fixed_exit = "jp-vps"`, `require_stable_egress = true`, `on_failure = NotifyAndBlock`
- **When** `jp-vps` 变为不健康或 `stable_egress == false`
- **Then** 返回 `PolicyDecision::Blocked { notify: true, .. }`，绝不自动切换至其他出口

## FP-N3-03 自定义 DNS 改写与广告过滤（U07）
- **Given** 节点配置 `Override("api.dev.test" -> 10.0.0.5, ttl=30)` 与 `BlockNxdomain("ads.example.com")`
- **When** 完整节点 DNS 收到 `api.dev.test` 的 A 查询
- **Then** 直接返回 `10.0.0.5`（TTL 30），不向公网解析
- **When** 收到 `track.ads.example.com` 的查询
- **Then** 返回 `NXDOMAIN`

## FP-N3-04 白名单局部解除过滤与私有域名零泄露（U07）
- **Given** 节点同时配置 `BlockNxdomain("ads.example.com")` 与 `Allow("ok.ads.example.com")`
- **When** 查询 `ok.ads.example.com`
- **Then** `Allow` 优先命中并放行；`.internal` 域名始终归入 `PrivateInternal`，绝不向公网泄露

## FP-N3-05 服务级健康分类不臆断 403 为 IP 封禁（U09）
- **Given** 目标服务返回 HTTP 403 / 429 / 503 / 200
- **When** 执行 `classify_http_status`
- **Then** 200 → `Healthy`；429 → `Degraded / HttpRateLimit`；403 → `PolicyRestricted / Unknown`（不臆断为 IP 封禁）；503 → `Unavailable / AppError`

## FP-N3-06 本地脱敏连接/DNS 事件观测（U09）
- **Given** 节点处理 DNS 查询与出站请求
- **When** 通过 `nexus flow ls` 或 `CtlRequest::FlowRecent` 查询
- **Then** 返回按时间倒序的有限条数 `FlowEvent`（含目标、动作、出口、结果），不含任何请求正文、Cookie 或令牌
