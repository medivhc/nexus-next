# M11.4 功能点：补齐多路径（批量两倍、经中继的路径、Android）

M5 留下的三处缺口（`docs/measurements/M5.md` 的「还没测到的」、手册的已知限制）：两条链路的批量吞吐约为一条的 1.5 倍；
经中继的路径没有测过；Android 上没有多路径和计费网络识别。

## 模型

- **批量**（R85）：两条不计费的链路时，批量传输的吞吐接近两条之和，包括链路状态刚变过（刚建立连接、
  计费的接口改回不计费）之后的第一次传输。每条路径各自的拥塞控制（BBR）在路径只有零星流量时不能把那段时间的
  测量当作「带宽已经到顶」。
- **经中继的路径**（R86）：设置了中继时，到另一台设备的连接里除了直连路径还一直开着一条经中继的路径，
  状态是 Backup（不承担数据）。直连路径都出现超时（都可疑）时，这些路径上在途的数据马上转到中继路径上重发，
  之后的数据也走中继；直连恢复后（下一次检查连接时重新打洞，5 秒内）数据回到直连。
  同一规则也适用于计费的 Backup 路径：不计费的路径都可疑时，计费的路径马上接管。
- **Android**（R87、R88）：应用跟踪系统的每个网络（ConnectivityManager，不含 VPN），把接口名和系统给的
  「是否计费」（没有 `NOT_METERED` 能力，且不是运营商临时不计费）交给核心；核心查看接口时，系统报告过的接口
  按系统的结果，其余按名字识别（和 Linux 一样）。系统在有 Wi-Fi 时会关掉移动数据，所以应用请求蜂窝网络一直在线
  （启动参数 `--ez multipath false` 时不请求）。核心的多路径和 Linux 是同一份代码：每个接口的地址都打洞、
  包从源地址所在的接口发出。

## FP-11.4-01 批量接近两倍（R85）
- Given laptop 和 home 之间两条独立链路，各限速 20 Mbit/s，各 20 毫秒往返
- When link2 标为计费，从 home 取 16 MB 的文件（只有一条承担批量），连续三次
- Then 每次都不低于限速的 80%
- When link2 改回自动识别，紧接着取 16 MB，连续三次
- Then 每一次（包括第一次）都超过只有一条时的 1.7 倍，两条链路各承担 35%–65%

## FP-11.4-02 直连都断，会话转到中继（R86）
- Given 同上的两条链路（不限速），home 上有中继，两台设备都用它
- Then 直连都好时，`nexus path home` 除了两条直连路径还列出一条中继路径
- When laptop 上 `nexus exec home -- 每 20 毫秒输出一行`，丢弃两条链路上的所有 UDP（TCP 照常，中继可达）
- Then 输出的最长停顿不超过 3 秒，命令没有结束；`nexus path home` 只剩中继路径
- And 这时取一个 4 MB 的文件成功，数据经中继路径
- When 恢复 UDP
- Then 20 秒内两条直连路径重新出现，之后取文件经中继的不超过 10%

## FP-11.4-03 不计费的都断时计费的马上接管（R86、R60）
- 由 FP-11.4-02 的规则覆盖：Backup 路径（中继或计费的接口）在 Available 路径都可疑时算作健康路径。
  M5.2 的 FP-5.2-02（计费的链路不走批量）照常通过。

## FP-11.4-04 Android：计费状态按系统（R88）
- 系统报告 `wlan0` 计费（计费的 Wi-Fi 热点）、`rmnet_data0` 不计费（不限量套餐）时：`nexus iface` 里
  `wlan0` 的 `auto_metered` 为 true、`rmnet_data0` 为 false；系统没有报告的接口（`rndis0`）仍按名字识别（单元测试）
- 应用启动后，`nexus iface` 里系统报告的网络（redroid 上是 `eth0`，不计费）和系统的结果一致；日志里有「网络：…」（实测）

## FP-11.4-05 Android：多条网络都用上（R87）
- Android 上的核心（同一份多路径代码，交叉编译到 x86_64）有两个接口连到 home 时，`nexus path home` 列出两条直连路径；
  丢弃正在用的那条，输出 1 秒内恢复（实测：redroid 和宿主共用网络，在宿主上加两条 veth 链路到 home 的命名空间）
- 应用请求蜂窝网络一直在线（`CHANGE_NETWORK_STATE`）；没有蜂窝网络的设备上请求失败只记日志，不影响启动
