# M5.2 功能点：交互冗余与计费网络

## 模型

- **交互冗余**：优先级不低于 8 的流（Nexus 的交互流量：终端会话、按键、名册和查询请求）的数据，
  在一条路径上发出后，再在另一条健康的路径上发一次；接收方取先到的（QUIC 的流本来就丢弃重复的数据）。
  已经被确认的数据不再重发；另一条路径一直不发包时，待重发的数据最多记 512 段。
  普通流量（`nexus exec` 的输出）和批量流量不冗余。
- **计费网络**：本机每 5 秒查看一次网络接口。按流量计费的接口自动识别（Linux）：蜂窝网络设备（`DEVTYPE=wwan`、
  原始 IP 类型的接口）和蜂窝、USB 网络共享的接口名（`wwan`、`rmnet`、`ccmni`、`usb`、`rndis`）。
  `nexus iface <接口> --metered on|off|auto` 手动设置（保存，重启后仍然有效）。
- 计费接口上的直连路径是 Backup：只在没有别的可用路径（或别的路径可疑）时承担普通和批量流量；
  交互冗余照样经过它。对端也按 Backup 对待（QUIC 多路径的 PATH_STATUS），所以对端发过来的批量数据也不走它。
- `nexus iface` 列出接口、地址、是否计费、是自动识别还是手动设置；`nexus path` 里计费的路径标明「计费」。

## FP-5.2-01 交互流量两条路都走（R58）
- Given 两条链路，laptop 上 `nexus ssh home` 的会话每 20 毫秒输出一行
- Then 两条链路上的流量相当（少的一条至少是多的一条的一半）
- When 正在用的链路随机丢 30% 的包
- Then 终端输出的最长间隔不超过 0.2 秒
- And 同样的丢包下 `nexus exec`（不冗余）的间隔作对比记录

## FP-5.2-02 计费的链路不走批量（R60）
- Given laptop 在 link2 上的接口标为计费（`nexus iface <接口> --metered on`）
- When 从 home 取一个 16 MB 的文件（批量流量）
- Then link2 上的流量不超过总量的 10%
- When 改回自动识别（`--metered auto`）
- Then 之后的批量传输两条都走（见 M5.3）

## FP-5.2-03 自动识别（R60）
- 接口名 `wwan0`、`wwp0s20f0u2i12`、`rmnet_data0`、`ccmni1`、`usb0`、`rndis0` 识别为计费；
  `eth0`、`wlan0`、`enp3s0`、`wlp2s0`、`docker0` 不计费（单元测试）
- agent 不能改设置（管理操作）

## 测试方式

`tools/multipath_check.py --only redundancy,metered`（需要 root）；自动识别是 `nexus-fabric-iroh` 的单元测试。
