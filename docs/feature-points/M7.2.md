# M7.2 功能点：终端会话在常驻程序重启后保留

## 模型

- 每个终端会话由一个独立的**持有进程**管理（同一个 `nexus` 二进制，隐藏的子命令 `nexus session-hold`）：
  它打开伪终端、启动 shell、自己解析终端输出（保持当前屏幕），在数据目录的 `sessions/` 里开一个只有本账号能连的
  套接字，等常驻程序连上来。持有进程自成一个进程组：常驻程序退出、被结束或在前台被 Ctrl-C 时它不受影响。
- 常驻程序创建会话时启动持有进程并连上它；启动时扫描 `sessions/`，连上每个还活着的持有进程，把会话恢复到列表里
  （名字、创建时间、尺寸不变）。连上时持有进程先发一段「把终端重绘成当前屏幕」的数据，再接着发实时输出。
- 常驻程序和持有进程之间的协议也有版本：升级之后，新的常驻程序要能接管旧的持有进程（fixtures 检查编码不变）。
- 会话里的 shell 退出：持有进程把退出码交给常驻程序后退出，删掉自己的套接字。常驻程序不在时 shell 退出的，
  持有进程等常驻程序最多 10 分钟，没等到就自己退出。
- systemd 的单元要用 `KillMode=process`：否则重启服务时 systemd 会把持有进程一起结束（手册写明）。
- 没有持有进程的环境（Android、仿真）照旧在常驻程序进程里运行会话。

## FP-7.2-01 重启后接回（R66）
- Given laptop 上 `nexus ssh home` 连着会话 main，屏幕上有 `before`
- When home 的常驻程序被结束再启动
- Then laptop 的客户端自动接回，屏幕上还有 `before`；接着输入命令照常执行
- And `nexus session ls home` 里 main 还在，创建时间不变

## FP-7.2-02 不在时的输出（R66）
- Given 会话里在跑 `sleep 2; 输出 during`
- When 常驻程序在输出之前被结束，3 秒后再启动
- Then 接回后屏幕上有 `during`

## FP-7.2-03 结束（R66）
- 重启后 `nexus session kill home main`：会话结束，连着的客户端退出，持有进程退出、套接字删掉
- 重启后在会话里 `exit 3`：客户端以 3 退出
- 常驻程序不在时 shell 退出：常驻程序回来后 `session ls` 里没有这个会话，持有进程不在了

## FP-7.2-04 协议不变（R66）
- 常驻程序和持有进程之间的每种消息有样例，编码和 fixtures 里的逐字节相同（`nexus-sys-real` 的测试）

## 测试方式

验收场景 `crates/nexus-cli/tests/session_restart.rs`（只在真实后端：要真的结束和启动常驻程序），
`nexus-sys-real` 的单元测试（持有进程的协议、fixtures）。测试工具结束时清理留下的持有进程。
