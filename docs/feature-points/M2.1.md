# M2.1 功能点：登记通行密钥

网页节点的身份是登记进网络的**通行密钥**（WebAuthn 凭据，P-256）。公钥写在名册里，由根密钥签名，
所以每台设备都能自己验证网页登录，不需要在线的签发方。

登记的过程：

1. 管理设备上 `nexus web enroll --label phone`：生成一次性的登记码，输出一个链接
   `https://bewith.link/#enroll=<登记码>&node=<管理设备>&relay=<中继>`。
2. 在要用的设备（通常是手机）上打开链接，页面创建通行密钥，经中继把公钥交给管理设备（协议 `nexus/web/2`）。
3. 管理设备核对登记码，把公钥写进名册并推送到各设备。

M2.1 实现管理设备一侧和登记协议；页面还没有，测试里由「网页节点核心」加一个软件实现的认证器扮演浏览器，
它们之后就是浏览器里运行的代码。

## FP-2.1-01 通行密钥的签名校验（R28 的基础）
- Given 一个登记过的通行密钥（公钥、依赖方 bewith.link）
- When 校验一次登录断言：客户端数据、认证器数据、签名
- Then 只有以下全部成立才通过：类型是 webauthn.get；挑战等于设备发出的那个；来源是 https://bewith.link
  （开发时允许 http://localhost 任意端口）；认证器数据里的依赖方哈希匹配；用户在场和用户验证两个标志都置位；
  签名用登记的公钥验证通过
- And 真实 Chromium 产生的断言能通过校验；改动其中任何一个字节都不能通过

## FP-2.1-02 发起登记（R29）
- When 在管理设备上 `nexus web enroll --label phone`
- Then 输出登记链接和到期时间（默认 10 分钟）；`--json` 时是结构化的
- When 在不是管理设备的设备上发起
- Then 退出码 106
- When 名字已被一个有效的通行密钥使用
- Then 退出码 107

## FP-2.1-03 完成登记（R29）
- Given 管理设备发起了登记
- When 浏览器（测试里是网页节点核心加软件认证器）用登记链接里的信息，经协议提交新建的通行密钥
- Then 名册里出现这个通行密钥，名字是 phone，权限是默认的 `term.session.*@**` 和 `node.info@**`；名册推送到所有设备
- When 同一个登记码再用一次，或者登记码已过期，或者登记码是编出来的
- Then 登记被拒绝，名册不变

## FP-2.1-04 列出与撤销（R29）
- When `nexus web ls`
- Then 列出登记的通行密钥：名字、权限、登记时间；在任何设备上都能看到（来自名册）
- When 管理设备 `nexus web revoke phone`
- Then 它从名册里移除，新名册推送到各设备；`web ls` 里不再有它
- When 撤销一个不存在的名字
- Then 退出码 109

## FP-2.1-05 自定义权限（R29、R33）
- When `nexus web enroll --label kiosk --grant node.info@home`
- Then 登记后这个通行密钥的权限只有 `node.info@home`
