# M11.1 功能点：远程桌面（让现成方案跑在 Nexus 的网络上）

路线（docs/roadmap.md「更后面」）：先不自己做画面编码，让系统自带或常见的 VNC / RDP 服务端和查看器经 Nexus 连起来。
Nexus 负责的是：找到本机的远程桌面服务并发布、在使用方开一个只给本机用的端口、启动查看器、每个连接经 Nexus 到对方。
画面、输入、剪贴板、登录都是现成方案自己的事。

## 模型

- 远程桌面就是一个发布的服务，协议写 `vnc` 或 `rdp`（`nexus publish desktop --port 5900 --proto vnc` 也可以）。
  服务的 `proto` 本来就是字符串：不改协议，不加 `WIRE_MINOR`；旧版本的设备照样能 `nexus connect` 它。
  发布时常驻程序检查协议名，`vnc`、`rdp` 加进可用的列表：发布要本机的常驻程序是 M11.1 以后的版本；
  使用方是旧版本时 `nexus ls`、`nexus connect` 照常（`nexus open` 会说它不是网页服务）。
- 被看的设备：`nexus desktop share [--name <名字>] [--port <端口>] [--proto vnc|rdp] [--json]`
  - 不给 `--port`：依次试本机的 5900、5901（VNC）和 3389（RDP），用第一个答话的。
  - 识别：连上后 1 秒内对方先说 `RFB ` 开头的话是 VNC；对 X.224 连接请求回 `0x03 0x00`（TPKT）的是 RDP。
    给了 `--proto` 时只确认端口能连上，不识别（有的服务端要先认证才说话）。
  - 发布成服务（默认名字 `desktop`，地址 `127.0.0.1:<端口>`），标准输出一行：
    `已发布远程桌面 <本机>/desktop（vnc，本机端口 5900）。其他设备：nexus desktop open <本机>`。
  - 本机没有在运行的远程桌面服务：退出码 109，说明按系统怎么打开（macOS：系统设置 → 通用 → 共享 → 屏幕共享；
    Windows：设置 → 系统 → 远程桌面；Linux：wayvnc、x11vnc 或 GNOME 的远程桌面），以及只监听 127.0.0.1 的建议。
  - 端口能连上、但认不出是什么、又没给 `--proto`：退出码 107，提示加 `--proto`。
- 使用方：`nexus desktop open <设备>[/<服务>] [--port <端口>] [--no-viewer]`
  - 不给服务名时，在那台设备能用的服务里找协议是 `vnc` 或 `rdp` 的：只有一个就用它；没有：109，提示在那台设备上
    运行 `nexus desktop share`；多于一个：107，列出它们的名字。
  - 和 `nexus open` 一样先确认服务能用，再在 `127.0.0.1` 上开端口（默认系统挑），每个连接各自接到服务，直到 Ctrl-C。
  - 地址：`vnc://127.0.0.1:<端口>` 或 `rdp://127.0.0.1:<端口>`。标准输出一行：
    `home/desktop → vnc://127.0.0.1:<端口>（按 Ctrl-C 停止）`。
  - 查看器：环境变量 `NEXUS_DESKTOP_VIEWER` 有值时执行它，地址作为最后一个参数；否则按系统和协议选第一个找得到的：
    | | VNC | RDP |
    | --- | --- | --- |
    | macOS | `open vnc://127.0.0.1:<端口>`（屏幕共享） | `open rdp://full%20address=s:127.0.0.1:<端口>`（Windows App） |
    | Windows | `vncviewer 127.0.0.1::<端口>` | `mstsc /v:127.0.0.1:<端口>` |
    | Linux | `vncviewer 127.0.0.1::<端口>`、`remmina -c vnc://…`、`xdg-open vnc://…` | `xfreerdp3 /v:…`、`xfreerdp /v:…`、`remmina -c rdp://…` |
  - 找不到查看器或启动失败：在标准错误说明一句（装什么、或手动连上面的地址），照样服务。`--no-viewer` 不启动。
  - 给了路径（`home/desktop/x`）：107。
- `nexus open home/desktop` 遇到 `vnc` / `rdp` 服务时，和 `nexus desktop open home/desktop` 一样（`--no-browser` 即不启动查看器）。
- `nexus desktop ls [--json]`：在线设备上能用的远程桌面，一行一个：`home/desktop  vnc`；JSON 是
  `{"desktops": [{"path", "device", "name", "proto"}]}`。离线或问不到的设备跳过。

## FP-11.1-01 发布本机的远程桌面（R77）
- Given home 上有一个只监听本机、先说 `RFB 003.008\n` 的服务
- When home 上 `nexus desktop share --port <端口>`
- Then 发布了服务 `desktop`，协议 `vnc`；`nexus ls home` 能看到它
- And `--name screen --proto rdp --port <端口>` 发布成 `screen`，协议 `rdp`（给了协议就不识别）
- And 端口上什么都没有：109，说明里有怎么打开屏幕共享；端口上的服务不说话也没给 `--proto`：107

## FP-11.1-02 打开另一台设备的桌面（R77）
- Given home 发布了 vnc 的 `desktop`，laptop 在同一网络
- When laptop 上 `nexus desktop open home`，`NEXUS_DESKTOP_VIEWER` 是一个记下参数的程序
- Then 查看器收到 `vnc://127.0.0.1:<端口>`；连这个端口读到的是 home 上服务说的 `RFB 003.008\n`，写进去的内容服务收得到
- And 连几次都成功（每个连接各自接到服务），标准输出里有这个地址
- And `nexus open home/desktop` 效果一样；`--no-viewer --port <p>` 不启动查看器，地址是 `vnc://127.0.0.1:<p>`

## FP-11.1-03 打不开（R77）
- home 上没有远程桌面：109，提示 `nexus desktop share`
- home 上有两个远程桌面又没给名字：107，说明里有两个名字
- 指定的服务是 tcp：107；带路径：107；都不开端口
- 查看器启动失败：照样服务，标准错误里说明

## FP-11.1-04 列出远程桌面（R77）
- `nexus desktop ls`：列出 home/desktop（vnc）和 home/screen（rdp），不列 tcp 和 http 服务
- `--json` 的形状如上

## FP-11.1-05 识别和查看器的选择（R77，单元测试）
- 识别：`RFB 003.008\n` → vnc；`0x03 0x00 …` → rdp；不说话或别的 → 认不出
- 各系统、各协议下查看器的命令行和上表一致；`NEXUS_DESKTOP_VIEWER` 优先

## 不在这一步

- 网页节点里看远程桌面（R78，M11.6）：需要网页服务支持 WebSocket（R71 现在不支持），再放一个 noVNC 类的页面。
- 多路径上把远程桌面当交互流量调度、画面延迟的测量；会话录屏和临时分享远程桌面。
- 真实服务端和查看器（macOS 屏幕共享、Windows 远程桌面、wayvnc）的互通要在用户的设备上走一遍（和 M7.0 一起）。

## 测试方式

验收场景 `crates/nexus-cli/tests/desktop.rs`（只在真实后端：要真的在本机开端口、执行查看器程序）。
假的 VNC 服务端是测试里的一个 TCP 服务：先说 `RFB 003.008\n`，之后把收到的原样送回。
识别和查看器命令行是 `crates/nexus-cli/src/desktop.rs` 里的单元测试。
