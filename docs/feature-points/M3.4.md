# M3.4 功能点：完整节点（虚拟网卡与名字解析）

`nexus daemon --tun nexus0 [--tun-net 198.18.0.0/16]`：常驻程序建一张虚拟网卡，在上面运行名字服务。
系统里的任何程序不设代理，按名字就能访问网络里的服务。

- 网段里第一个地址是网段本身，第二个给本机一侧（虚拟网卡），第三个是名字服务，其余是本机临时地址，最后一个是广播。
- 名字服务回答 `<服务>.<设备>.internal`：给这个名字一个本机临时地址（同一个名字总是同一个地址）。
  连这个地址的任何端口，都经 Nexus 到那台设备的那个服务（授权、审计同 `nexus connect`）。
- 路由规则里不是直连的域名（拒绝、经设备出去、上游代理）也解析成本机临时地址，连接按规则走。
  其余名字照常解析（用本机的解析）。
- 让系统把 `.internal` 交给名字服务：有 systemd-resolved 时常驻程序自动配置（`resolvectl`），
  否则在日志里说明怎么配。
- 第一版只接 TCP；地址段规则（`--cidr`）不经虚拟网卡（只在统一入口生效）。节点自己的稳定地址（IPv6）
  在需要按设备访问时再做。

决定的变更：产品文档设想「节点地址 IPv6（ULA）」。按服务发布的模型里，使用方只访问服务，不访问设备的任意端口，
所以先给服务本机临时地址（「服务经名字解析得到本机临时地址」），设备地址推迟。

## FP-3.4-01 名字解析成本机临时地址（R43）
- Given home 发布了 web；laptop 是完整节点
- When 查询 web.home.internal 的 IPv4 地址
- Then 得到网段里的一个地址；大小写不同的同一个名字得到同一个地址；IPv6 查询是没有回答的 NOERROR
- When 普通程序不设代理连这个地址的 80 或 8080 端口，发 HTTP 请求
- Then 拿到 home 上服务的回应
- When 查询 web.nowhere.internal 或 home.internal
- Then NXDOMAIN
- When 查询 nope.home.internal（设备在，服务不在）并连接
- Then 名字可以解析，连接被关闭
- And `nexus status --json` 里有 `tun`：网卡、网段、名字服务的地址

## FP-3.4-02 规则里的域名经虚拟网卡按规则走（R43、R41）
- Given laptop 规则：far.test 交给上游 SOCKS5，blocked.test 拒绝；laptop 是完整节点
- When 查询 www.far.test 并连接、发 HTTP 请求
- Then 连接交给上游，目标是 www.far.test:80
- When 查询 blocked.test 并连接
- Then 连接被关闭
- When 查询 localhost
- Then 127.0.0.1
