# M4.3 功能点：挂载（Linux）

## 模型

- `nexus drive mount <工作区路径> <目录>`：把工作区（或其中一个子目录）挂到一个空目录上，命令在前台运行，
  直到 `fusermount -u <目录>`、Ctrl-C 或 SIGTERM。传统程序（`ls`、`cat`、编辑器、编译器）直接用这个目录。
- 看到的是工作区的**工作树**（最新提交加上本机未提交的改动），和 `drive ls` / `drive cat` 一致。
- **写入只落本机**：在挂载里新建、修改、删除、改名、`chmod +x`，都成为本机的未提交改动（`drive status` 可见），
  不复制到任何设备，直到 `nexus drive commit`。文件在关闭时写入工作树；没关闭前的写入只在挂载进程里。
- **同步进来的修改可见**：`drive sync` 让工作树前进后，挂载在几秒内显示新内容，不会继续给程序旧的属性或内容。
- **修改时间**：工作区不记录修改时间。挂载里文件的修改时间是挂载开始的时间；内容变了（本机写入或同步进来），
  修改时间变成变化被看到的时间。这样 `make`、`cargo` 这类按修改时间判断的工具能看出改动。
- 权限：文件 0644，可执行文件 0755，目录 0755，属于运行挂载的用户。
- 授权：挂载进程是本机的普通客户端；用 `--agent` 时，读需要 `drive.read`，写需要 `drive.write`。

## FP-4.3-01 挂载后像普通目录一样读（R53）
- Given 工作区 work 有 `Cargo.toml`、`src/main.rs`、可执行的 `run.sh`、符号链接 `main-link -> src/main.rs`、一个 3 MiB 的文件
- When `nexus drive mount work:/ <目录>`
- Then `ls` 列出这些文件；`cat` 内容一致；`run.sh` 可以直接执行；`readlink main-link` 是 `src/main.rs`；
  大文件用 `dd` 读一段和原文件对应的一段一致
- And 在挂载里 `cargo build`（目标目录在挂载外）成功，生成的程序能运行
- When 只挂子目录 `work:/src`
- Then 目录里只有 `main.rs`

## FP-4.3-02 写入只落本机（R49、R53）
- Given work 已提交并复制到 anchor，laptop 挂载了它
- When 在挂载里新建文件、改一个文件、`mkdir`、删除文件、`mv` 改名、`chmod +x`
- Then `drive status work` 列出这些改动；`drive cat` 读到新内容
- And anchor 上 work 的头不变（没有提交就不复制）
- When `drive commit work`
- Then 提交推到 anchor，anchor 读到新内容

## FP-4.3-03 同步进来的修改可见（R50、R53）
- Given laptop 和 desktop 都有 work，desktop 挂载了它，程序已经读过 `notes.txt`
- When laptop 改 `notes.txt`（长度也变了）、新增 `new.txt` 并提交；desktop `drive sync work`
- Then 3 秒内 desktop 挂载里 `cat notes.txt` 是新内容（长度正确），`new.txt` 出现，`notes.txt` 的修改时间变了

## FP-4.3-04 卸载与错误（R53）
- `fusermount -u <目录>` 后命令以 0 结束，目录恢复为空
- 收到 SIGTERM 时卸载并以 0 结束；已关闭的文件的写入都在工作树里
- 工作区不存在：109；路径不是目录：107；挂载点不存在或不是空目录：107
- 没有 `drive.read` 授权的 agent 不能挂载（105）；只有 `drive.read` 的 agent 能挂载但写入失败（权限错误），工作树不变

## 实现说明与限制

- 挂载进程用一个单独的线程和常驻程序说话；FUSE 回调同步等待它。卸载时主线程等 FUSE 线程收尾，不会互相卡住。
- 内核缓存属性和目录项 1 秒，每次打开文件丢弃页缓存；挂载每 0.5 秒检查一次工作树的根，变了就丢掉目录缓存。
  所以同步进来的修改约 1.5 秒内可见（场景要求 3 秒）。
- 以写方式打开已有文件时就确认有写权限（否则多数程序在关闭时失败也不报告）。
- 不支持硬链接、扩展属性、文件锁；修改时间不保存在工作区里（见上面的「修改时间」）。
- 非 root 用户挂载需要 `/dev/fuse` 可读写和 setuid 的 `fusermount3`（GitHub 的 runner 上在工作流里准备）。
