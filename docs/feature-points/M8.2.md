# M8.2 功能点：网页端打开已发布的网页服务

## 模型

- **复用现有协议，不升主版本**：浏览器节点继续使用 `Proto::Rpc`（协议主版本 19）：
  - 通过 `Request::SvcList` 发现目标设备上当前通行密钥有权连接的已发布服务，页面侧仅展示 `proto == "http"` 的网页服务（`tcp` 服务不在网页内嵌打开）。
  - 通过 `Request::SvcConnect { name }` 经目标设备鉴权并审计后建立直通目标本机端口的双向字节流；`nexus-web-core` 在流上完成 HTTP/1.1 请求编码与响应解析（支持 `Content-Length`、`Transfer-Encoding: chunked` 与读至 EOF，并设置单次响应 32 MiB 内存上限）。
- **最小权限与审计（R71、R33、R37）**：
  - `nexus web enroll` 默认权限保持不变（不含 `svc.connect`）；网页端打开服务需显式授权（例如 `--grant 'svc.connect@home/svc/web'` 或 `--grant 'svc.connect@**'`，同时保留 `node.info` 发现服务列表）。
  - 每次 HTTP 转发连接都在目标设备经过 `authz::decide` 判定并写入 `audit.log`（主体为通行密钥名字，能力为 `svc.connect`，资源为 `<设备>/svc/<服务>`）。
- **按需注册 Service Worker 与 R32 协调**：
  - 仅在用户点击打开某个网页服务时才注册极简 `web/sw.js`；纯终端和文件浏览全程不注册 Service Worker。
  - `sw.js` 零存储（不写 `CacheStorage`/`IndexedDB`）、不持任何密钥，仅把拦截到的 `/_svc/<设备>/<服务>/*` 以及已绑定服务 `iframe`（按 `clientId` 追踪）的绝对根路径请求经 `MessageChannel` 转给主页面内存中的 `Session`。
  - 离开服务视图或关闭页面时主动注销 `sw.js`；主页面关闭后即使 SW 尚未卸载，所有 `/_svc/*` 请求均直接返回 `503`，无法恢复登录（满足 R32）。
- **重定向与 Cookie 隔离**：
  - 响应头 `Location: /next` 自动改写为 `/_svc/<设备>/<服务>/next`；`Set-Cookie` 的 `Path` 收窄至 `/_svc/<设备>/<服务>/`，防止被代理服务向 Nexus 主页面根路径写入 Cookie。
- **已知限制**：
  - 浏览器 Service Worker 规范无法拦截原生 `WebSocket`；M8.2 承诺 HTTP/1.1 服务（静态页、管理面板、REST/表单），依赖 WebSocket 的应用请使用本机 `nexus connect` / 统一入口。

## FP-8.2-01 最小权限与服务发现（R71、R33、R37）
- Given 设备 `home` 发布了 HTTP 服务 `web`、HTTP 服务 `admin` 和 TCP 服务 `echo`
- When 用默认权限（不含 `svc.connect`）的通行密钥登录网页节点
- Then `services("home")` 返回空列表，直接 `http_fetch("home", "web", ...)` 返回 `Denied`
- When 另用带 `--grant 'svc.connect@home/svc/web'`（及 `node.info@**`）的通行密钥登录
- Then `services("home")` 仅返回 `web`，`http_fetch("home", "web", ...)` 成功，访问 `admin` 返回 `Denied`，且 `home` 的 `audit.log` 记录 `svc.connect` 的允许与拒绝

## FP-8.2-02 HTTP/1.1 请求与响应转发（R71）
- Given `home` 上运行着 HTTP 服务 `web`
- When 浏览器节点经 `http_fetch` 发送带自定义路径、请求头与正文的 HTTP/1.1 请求
- Then 正确收到状态码、响应头与响应体（支持 `Content-Length`、`Transfer-Encoding: chunked` 与读至 EOF），且拦截非法换行（防 CRLF 注入）

## FP-8.2-03 重定向与 Cookie 路径隔离（R71）
- Given 响应包含 `Location: /dashboard` 与 `Set-Cookie: sid=1; Path=/`
- When 经过网页端响应头改写
- Then `Location` 改写为 `/_svc/home/web/dashboard`，`Set-Cookie` 路径收窄为 `/_svc/home/web/`；协议相对路径 `//example.com` 和外部 URL 不被错误改写

## FP-8.2-04 后端未运行与超限保护（R71）
- Given `home` 发布了 `dead` 服务但对应本机端口未监听
- When 浏览器节点调用 `http_fetch("home", "dead", ...)`
- Then 返回 `Unreachable` 错误；超过 32 MiB 的响应在解析时被中止并报错

## FP-8.2-05 撤销通行密钥与关闭即离开（R31、R32、R71）
- Given 网页端正在访问 `home/web`
- When 管理设备执行 `nexus web revoke <label>`
- Then 后续 `services` 与 `http_fetch` 请求立即返回 `Denied`

## 测试方式

- **L1 `nexus-web-core` 单元测试**：HTTP/1.1 请求编码与 CRLF 拦截、`Content-Length` / `chunked` / EOF 响应解析、响应超限截断报错、`Location` 与 `Set-Cookie` 改写。
- **L2 / L3 验收场景**（`crates/nexus-cli/tests/web_service.rs`，仿真与真实双后端）：覆盖 FP-8.2-01、FP-8.2-02、FP-8.2-04、FP-8.2-05。
