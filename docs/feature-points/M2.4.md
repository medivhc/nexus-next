# M2.4 功能点：锚点

锚点是一台常开、有公网地址的设备（通常是 VPS），一条命令同时提供：

- **中继**：网页节点只能经中继通信；设备之间直连不通时也经它转发。连接仍端到端加密，锚点看不到内容。
- **页面**：在 `https://<域名>/` 提供网页节点的页面；通行密钥绑定这个域名。
- **证书**：自动向 Let's Encrypt 申请和续期，缓存在数据目录里。

```
nexus daemon --anchor bewith.link --page-dir /srv/nexus/web
```

同一个 HTTPS 端口上，`/relay` 等中继路径交给内置中继，其余路径是页面。
锚点本身也是网络里的一台设备（加入、授权、审计都和其他设备一样）。

管理设备上 `nexus anchor set https://bewith.link` 把锚点写进名册，各设备收到名册后把它加为中继（不需要重启），
之后的登记链接默认指向锚点上的页面。

## FP-2.4-01 一条命令起锚点（R35）
- When `nexus daemon --anchor <域名> --page-dir <页面目录>`（测试里用 `--anchor-dev 127.0.0.1:<端口>`：只监听本机、http，
  锚点地址是 `http://localhost:<端口>`）
- Then 同一个端口上：`/` 是页面，WebAssembly 文件类型是 `application/wasm`，目录之外的路径 404；中继路径是可用的中继
- When 不带 --page-dir、页面目录里没有 index.html，或开发用的锚点不是本机地址
- Then 启动失败，退出码 107，说明原因

## FP-2.4-02 名册里的锚点（R35）
- When 管理设备 `nexus anchor set <锚点地址>`
- Then 名册里记下锚点，推送到各设备；`nexus anchor show` 在任何设备上都能看到；各设备把它加为中继
- And `nexus web enroll` 不带 --page 时，登记链接指向锚点上的页面；带 --page 时用给出的
- When 不是管理设备
- Then 退出码 106
- When 地址不是 `https://主机[:端口]`（开发时允许 `http://localhost[:端口]`；通行密钥不接受 IP 地址作为域名）
- Then 退出码 107
- When `nexus anchor set --clear`
- Then 名册里不再有锚点，登记链接回到默认页面（已经加入的中继保留到重启）
- And 加入锚点之前保存的名册照样能读出、签名仍然有效；没有锚点的名册签名与之前逐字节相同

## FP-2.4-03 浏览器经锚点登录（R35、R28）
- Given 三台设备 laptop、home、anchor；laptop、home 只配置了锚点这一个中继
- When 只经中继的浏览器用登记链接登记通行密钥，再登录，连 home 的会话
- Then 全部成功；设备列表是 anchor、home、laptop

## FP-2.4-04 证书（R35）
- When 指定 --tls-cert 和 --tls-key
- Then 用这对证书和私钥提供 https；读不了时启动失败（107）
- And http 端口一律 301 重定向到 `https://<域名><原路径>`
- When 不指定证书（正式模式）
- Then 自动申请证书（TLS-ALPN-01，只需要 443 端口），缓存在数据目录的 acme/ 里，重启不重新申请；
  `--acme-staging` 先用测试环境走一遍流程
- 验证：自动申请需要真实域名，在 VPS 上验证（见 docs/anchor.md）

## FP-2.4-05 中继不被滥用（R35）
- 中继对所有连接开放（浏览器的临时身份不在名册里），每个连接限速 2 MiB/s，突发 8 MiB
