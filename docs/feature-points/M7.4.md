# M7.4 功能点：在浏览器里打开网页服务

## 模型

- `nexus open <设备>/<服务>[/<路径>] [--port <端口>] [--no-browser]`。
- 和 `nexus connect --listen` 一样先确认服务能用（存在、有授权、发布方的程序在运行），再读服务的说明：
  协议不是 `http` 时不开端口，退出码 107，提示用 `nexus connect`。
- 在 `127.0.0.1` 上开端口（默认系统挑一个空闲的，`--port` 指定），每个连接各自接到服务，直到 Ctrl-C。
- 网址：
  - 给了路径：`http://127.0.0.1:<端口>/<路径>`（路径原样保留，包括 `?` 后面的部分）。
  - 没给路径：服务说明的环境变量里第一个以 `http://{addr}` 开头的值，`{addr}` 换成 `127.0.0.1:<端口>`；
    没有时是 `http://127.0.0.1:<端口>/`。
- 标准输出一行：`home/web → <网址>（按 Ctrl-C 停止）`。
- 打开浏览器：环境变量 `BROWSER` 有值时执行它（网址作为最后一个参数）；否则 Linux 上 `xdg-open`、macOS 上 `open`、
  Windows 上 `cmd /c start`。`--no-browser` 不打开。打不开时在标准错误说明一句，照样服务。
- 浏览器发的 `Host` 是 `127.0.0.1:<端口>`：只认自己域名的网页服务（例如检查 `Host` 的）可能拒绝，这时用统一入口
  （`web.home.internal`）。

## FP-7.4-01 打开网页服务（R69）
- Given home 发布了网页服务 web（`--proto http`），laptop 在同一网络
- When laptop 上 `nexus open home/web`，`BROWSER` 是一个记下网址的程序
- Then 浏览器收到的网址是 `http://127.0.0.1:<端口>/`，用它取到的内容就是 home 上的服务给的
- And 同一个网址再取几次都成功（每个请求各自一条连接）

## FP-7.4-02 带路径、按说明拼网址（R69）
- `nexus open home/web/admin?tab=2`：网址以 `/admin?tab=2` 结尾
- web 发布时带 `--env BASE_URL=http://{addr}/v1`，`nexus open home/web`：网址以 `/v1` 结尾
- `--no-browser --port <p>`：不执行 `BROWSER`；标准输出里有 `http://127.0.0.1:<p>/`

## FP-7.4-03 打不开（R69）
- 服务不存在：109；`nexus open home`（没有服务名）：107
- 服务是 tcp（不是网页服务）：107，说明用 `nexus connect`；没有开端口
- 浏览器程序启动失败（`BROWSER` 指向不存在的程序）：照样服务，标准错误里说明打不开浏览器
