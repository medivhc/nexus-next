# M6.2 功能点：恢复管理设备

## 模型

- 管理设备 = 有网络根密钥的设备。`nexus init` 给出的恢复码就是根密钥（64 个十六进制字符）。
- `nexus recover <恢复码>`：在网络里的一台设备上，检查恢复码对应的公钥就是本机名册的根，保存根密钥；
  签一个新版本的名册（本机的角色改为管理设备，原来的管理设备改为成员），推送给能连上的设备。
- 恢复码里的空格和 `-` 忽略、不区分大小写（抄写时分组也行）。
- 原来签发过的 agent 列表只在原来的管理设备上，不在恢复后的设备上；`nexus agent revoke` 除了标签，
  也接受 agent 的完整标识（审计记录 `--json` 里的 `principal.agent_id`），不在本机列表里也能撤销。

## FP-6.2-01 在成员设备上恢复（R64）
- Given laptop 是管理设备，home、office 是成员；laptop 不在线了
- When home 执行 `nexus recover <laptop 建网时的恢复码>`
- Then 成功，输出名册版本；`nexus ls` 里 home 是管理设备、laptop 是成员
- And office 收到新名册（office 上 `nexus ls` 里 home 是管理设备）
- And home 能批准新设备（`device approve`），能把 laptop 移出名册（`device revoke laptop`）

## FP-6.2-02 失败时什么都不改（R64）
- 恢复码属于另一个网络：107「恢复码不属于这个网络」，名册版本不变，本机不是管理设备（`agent ls` 仍然 105/106）
- 不是 64 个十六进制字符：107
- 在管理设备上：106「本机已经是管理设备」
- 在不属于任何网络的设备上：106

## FP-6.2-03 撤销不在列表里的 agent（R64）
- Given laptop 签发了 agent ci（授权 term.exec@office），ci 在 office 上执行过命令
- When laptop 丢失，home 恢复；home 从 office 的审计记录（`nexus audit --json`）里取到 ci 的标识
- Then `nexus agent revoke <标识>` 成功；之后 ci 在 office 上执行被拒绝（105）
- And 不是有效 agent 标识、也不是本机列表里的标签：109
