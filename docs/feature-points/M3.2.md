# M3.2 功能点：本机统一入口与路由规则

常驻程序在本机开一个代理入口（SOCKS5 和 HTTP 代理在同一个端口上，按第一个字节区分）。
进来的每条连接交给同一个路由引擎决定去哪：

- 名字以 `.internal` 结尾的：`<服务>.<设备>.internal` 是网络里发布的服务，经 Nexus 连过去（和 `nexus connect` 相同的授权与审计）；
- 其余按路由规则：按域名后缀、精确域名、地址段匹配，第一条匹配的规则生效；都不匹配时直连。

出口目前只有「直连」和「拒绝」；经 Nexus 节点出去、交给上游 SOCKS5 在 M3.3。

`nexus run --use home/web -- 程序`：为用到的服务在本机开临时端口，按服务说明设置环境变量，再启动程序。

## FP-3.2-01 按名字访问服务（R40）
- Given home 发布了 http 服务 web；laptop 的常驻程序开着代理入口
- When 经 laptop 的入口（SOCKS5，目标 web.home.internal:80）发一个 HTTP 请求
- Then 拿到 home 上 web 的回应
- When 经 HTTP 代理（`GET http://web.home.internal/ HTTP/1.1`）请求
- Then 同样拿到回应
- When 经 HTTP 代理的 CONNECT（`CONNECT web.home.internal:443`）
- Then 建立隧道，之后的字节直接到服务
- When 名字对应的服务不存在、设备不存在
- Then SOCKS5 回应「主机不可达」，HTTP 代理回应 502，连接关闭

## FP-3.2-02 其余流量按规则走（R40、R41）
- Given 没有任何规则
- When 经入口访问网络里的一个普通地址（测试里是另一台机器上的服务）
- Then 直连
- When `nexus route add --domain example.test --reject`
- Then 访问 example.test 和它的子域名被拒绝（SOCKS5「规则不允许」，HTTP 403）
- When `nexus route explain web.home.internal:80`、`nexus route explain www.example.test:443`
- Then 分别说明走 Nexus 的哪台设备的哪个服务、命中哪条规则走哪个出口
- And `nexus route ls` 列出规则，`nexus route rm <编号>` 删除

## FP-3.2-03 入口只对本机开放（R40）
- 入口只监听本机地址；`--proxy` 给出非本机地址时，常驻程序拒绝启动（107）
- 第一个字节既不是 SOCKS5 也不是 HTTP 方法的连接直接关闭

## FP-3.2-04 nexus run（R45）
- Given home 发布了 web，环境变量模板 `BASE_URL=http://{addr}/v1`
- When `nexus run --use home/web -- sh -c 'echo $BASE_URL'`
- Then 输出 `http://127.0.0.1:<端口>/v1`，程序访问这个地址就是在用 home 上的 web
- And 程序退出后端口关闭；程序的退出码就是 nexus run 的退出码
- When 用到的服务不存在或没有授权
- Then 程序不启动，退出码同 nexus connect
