# M9.2 功能点：Vault（加密凭据同步、按条目授权、取用审计与吊销轮换清单）

对应需求：`FEATURES.md` **R74**（并遵循 **R12**、**R15**、**R17**、**R18**）。

## 设计要点

1. **端到端加密存储与定向同步**：
   - 每个 Vault 条目由管理设备写入（`nexus vault put <name> --device <dev>...`），按条目指定被授权的设备名列表。
   - 条目明文使用 `blake3` 派生流密码 + 16 字节随机盐 + 16 字节认证标签（`vault::seal` / `vault::open`；密钥由管理设备根私钥与目标设备公钥（或设备私钥与根公钥）的 X25519 共享秘密再加条目名经 `blake3::derive_key` 派生，每台设备一份密文，见 f686102）加密后落盘（`vault-v1`）并在网络上传输；未授权设备磁盘上绝不保存该条目。
   - 写入或删除条目时，管理设备立即通过 `Request::VaultPush` 向被授权的设备定向推送密文条目（对被移出授权列表的设备推送 `entry: None` 擦除本地副本）；设备也可通过 `nexus vault sync` 主动从管理设备拉取自己被授权的条目（`Request::VaultPull`）。
2. **按条目授权（设备 + Agent）与每次取用审计**：
   - 只有被列入该条目 `devices` 的设备才能持有或拉取该条目；未获授权的设备尝试拉取或读取时返回 `ErrorCode::Denied`。
   - Agent 访问本机或远端 Vault 时，必须持有 `vault.read@<设备>/vault/<条目名>` 授权（`nexus vault ls` 仅列出该 Agent 被授权看到的条目，遵守 R15「未授权即不可见」）。
   - 每一次 `nexus vault get <name>`（无论来自设备用户还是 Agent，也无论允许或拒绝）以及远端 `VaultPull` 均写入审计日志（`capability: "vault.read"`，`resource: "<设备>/vault/<条目名>"`）。
3. **吊销设备时列出需要轮换的条目**：
   - 管理设备记录每台设备曾被授权接触过的条目集合（`ever_devices`），并在 `nexus device revoke <device>` 时自动统计该被吊销设备接触过的所有现存 Vault 条目。
   - 支持 `nexus vault rotate-needed [--device <name>]`（JSON 与文本）随时查询因设备吊销而需要轮换的条目清单。
