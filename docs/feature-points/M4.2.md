# M4.2 功能点：跨设备同步与授权

## 模型

- **存储设备**：`nexus drive serve on` 的设备保存它负责的工作区的完整副本（锚点就是这样的设备）。
- **副本**：工作区创建时记下它的存储设备（`--replica <设备>` 指定，不指定时用网络里开了 serve 的设备）。
  创建时通知存储设备，它们从此知道这个工作区。
- **头**：存储设备上每个工作区有一个头（最新的提交）。设备提交后把新头告诉存储设备，存储设备从这台设备
  取走缺的对象（提交、目录树、清单、块），验证新头是旧头的后代（快进），然后更新头。不是后代时拒绝：这叫**分叉**。
- **同步**：`nexus drive sync <工作区>` 从存储设备取头；本机没有改动时快进；本机有存储设备没有的提交时推上去；
  两边各有对方没有的提交时报告分叉，用 `nexus drive merge <工作区>` 合并（按文件三方合并，两边改了同一个文件时
  保留本机的，对方的版本另存为 `<文件>.conflict-<设备>`，列出冲突），合并后再同步。永远不静默覆盖。
- **按需取**：别的设备上，目录结构（提交、树、清单）同步时全部取到本地；文件内容按读的范围取需要的块，取到的块缓存在本机。
- **授权**：存储设备判定每次取对象和更新头：能力 `drive.read` / `drive.write`，资源 `<存储设备>/drive/<工作区>`。
  名册里自己的设备默认可以；agent 需要明确授权；每次访问有审计。

## FP-4.2-01 存储设备与副本（R50）
- Given anchor 开了 serve，laptop 创建工作区 work（不指定副本）
- Then work 的副本是 anchor；anchor 的 `drive ls` 里有 work
- When laptop 导入文件并提交
- Then 提交复制到 anchor（anchor 的头等于 laptop 的头）；`drive where work:/` 显示副本 anchor 已同步
- When 没有开 serve 的设备、也没有指定副本时创建
- Then 工作区只在本机，`where` 显示只有一份

## FP-4.2-02 别的设备按需读（R48、R50）
- Given work 已复制到 anchor，desktop 还没有它
- When desktop `drive sync work`
- Then desktop 有 work 的历史和目录结构，但没有文件内容（`where` 显示内容本机 0%）
- When desktop 读一个大文件的一小段
- Then 只取到覆盖这一段的块（本机内容远小于文件大小），结果正确
- When laptop 已关机
- Then desktop 照样能读（从 anchor 取）

## FP-4.2-03 分叉与合并（R50）
- Given laptop 和 desktop 都在同一个头上
- When 两边各自修改并提交，laptop 先同步
- Then desktop 同步时报告分叉（本机提交和存储设备上的提交），desktop 的头不变，anchor 的头不变
- When desktop `drive merge work`
- Then 只有一边改的文件自动合并；两边都改的文件保留本机版本，对方版本另存为 `.conflict-laptop`，列出冲突
- And 合并提交有两个父提交；再同步成功，anchor 的头是合并提交

## FP-4.2-04 授权与审计（R51）
- agent 没有授权时不能读 work（105）；有 `drive.read@*/drive/work` 授权（任何设备上的 work；只给某台设备时写
  `<设备>/drive/work`，本机检查用 `<本机>/drive/<工作区>`）时可以读，不能写（`put` / `commit` / `create` 被拒）
- `drive ls` 只列出 agent 能读的工作区
- 本机和存储设备的审计里有 `drive.read` / `drive.write` 的记录

## FP-4.2-05 可解释（R52）
- `nexus drive where <路径>`：副本在哪些设备、是否已同步到副本、本机有多少内容、未提交的改动
- 没有副本或还没同步时明确显示「只在本机」
