# M5.0 技术验证（多路径）

探针：`tools/multipath_probe.py`（不属于产品代码；之后由 `tools/multipath_check.py` 取代）。机器：云端开发容器，2026-11-19。

## 1. 现在两条链路时会发生什么

laptop 和 home 各在一个网络命名空间里，中间两条独立的链路（不同网段）。中继关闭、不用公共地址发现。
laptop 上 `nexus exec home -- sh -c '每 20 毫秒打印一行'`，然后用 iptables 丢弃正在用的链路上的所有包
（接口不 down，就像信号没了）。

| | 结果 |
| --- | --- |
| 平时 | 只有一条链路有流量（另一条为 0） |
| 断开正在用的链路 15 秒 | 输出完全停住；另一条链路上有少量探测流量（约 8 KB），但数据没有换过去；恢复后接着输出 |
| 断开 45 秒 | 一直没有换路；约半分钟后连接超时，命令报「执行过程中连接中断」 |

结论：**现在没有故障转移**。一条路断了，会话停住直到连接超时。

## 2. 原因（iroh 1.4 / noq 1.4）

- noq（QUIC 实现）支持 QUIC 多路径：多条路径都标为 Available 时，按哪条有发送余量来排包（带宽可以叠加）；
  标为 Backup 的路径只在没有 Available 路径时用。没有「同一个包两条路都发」。
- iroh 在它之上管理路径：路径选择器（`PathSelector`，可以换）**只选一条**；客户端一侧会关掉其余的直连路径，
  只保留一条直连加上中继（中继是 Backup）。换路要靠重新打洞，而打洞的协调要经中继。
- iroh 用一个绑在所有接口上的 UDP 套接字：发往同一个目的地址时由系统路由决定走哪个接口。
  所以「有线和 5G 同时连到同一台机器」这种情况，现在根本用不上第二个接口。

## 3. 对阶段 5 的影响

产品要求（产品文档 6.2）：交互两条路同时发、实时媒体走最快的路、批量按容量分摊、单路径失效后保持逻辑会话并恢复、
按流量计费的网络只承担交互和故障接管。现在的传输一项都不满足，需要在 Nexus 这一层或传输层补上，方案见阶段 5 的实现方案。

## 4. 测量条件的限制

这台机器的内核没有 netem，不能加延迟和丢包，只能限速（tbf）和整条丢弃（iptables）。
有延迟、有丢包的链路要在别的机器上测（GitHub 的 runner 或 VPS）。
