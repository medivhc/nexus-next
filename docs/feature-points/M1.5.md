# M1.5 功能点：agent 身份、授权与审计

agent 的身份是一份**凭据**：管理设备签发的证书（写明 agent 的公钥、名字、有效期和授权条目），加上 agent 自己的私钥。
凭据是一段以 `nxa1-` 开头的文本。使用方式二选一，都不需要交互：

- 命令行参数 `--agent <凭据或凭据文件>`
- 环境变量 `NEXUS_AGENT=<凭据或凭据文件>`

带着凭据发出的每个请求，都由所在设备代 agent 签名，被访问的设备按证书里的授权判定。
授权条目写作 `能力@资源`，例如 `term.exec@home`、`term.session.*@home/session/build`。

## FP-1.5-01 签发凭据（R11）
- Given 管理设备 laptop
- When `nexus agent issue --label builder --grant term.exec@home --ttl 4h --json`
- Then 输出 agent 的标识、名字、到期时间和凭据；`--out 文件` 时凭据写进权限为 600 的文件
- When 在不是管理设备的 home 上签发
- Then 退出码 106（invalid_state）

## FP-1.5-02 只能做被授权的事（R12）
- Given builder 被授权 `term.exec@home`
- When 以 builder 的身份 `nexus exec home -- echo hi`
- Then 成功，输出 `hi`
- When 以 builder 的身份 `nexus session ls home`
- Then 退出码 105（denied）
- When 以 builder 的身份做管理操作（`device revoke`、`agent issue`）
- Then 退出码 105

## FP-1.5-03 身份跟着凭据走，不跟设备（R11）
- When 把 builder 的凭据带到 nas 上使用，`nexus exec home -- echo hi`
- Then 同样成功，审计记录里的主体是 builder，经由 nas

## FP-1.5-04 未授权即不可见（R15）
- Given builder 被授权 `term.session.*@home/session/build` 和 `term.session.list@home`，home 上有 main 和 build 两个会话
- When 以 builder 的身份 `nexus ls`
- Then 只列出 home
- When 以 builder 的身份 `nexus status nas` 或 `nexus exec nas -- true`
- Then 退出码 103（unknown_node），和 nas 不存在时一样
- When 以 builder 的身份 `nexus session ls home`
- Then 只看到 build

## FP-1.5-05 请求无法扩大权限（R16）
- When 把凭据里证书的授权条目改大（例如把 `home` 改成 `**`）后使用
- Then 退出码 105：证书签名不再成立
- When 用别的 agent 的私钥配上 builder 的证书
- Then 退出码 105

## FP-1.5-06 授权到期（R13）
- Given 签发时 `--ttl 2s`
- When 3 秒后以它的身份执行
- Then 退出码 105，原因是凭据已过期

## FP-1.5-07 撤销 agent（R14）
- Given builder 可以执行
- When 管理设备 `nexus agent revoke builder`
- Then 新名册推送到各设备，之后以 builder 的身份执行得到 105
- And `nexus agent ls` 里 builder 标记为已撤销

## FP-1.5-08 审计（R17）
- Given builder 在 home 上执行了一次被允许的和一次被拒绝的操作
- When 在 home 上 `nexus audit --json`
- Then 两条记录都在：时间、经由的设备、主体（agent 的名字和标识）、能力、资源、结果；拒绝的带原因
- And 同一个签名过的请求被重放时被拒绝（重放检测，由单元测试覆盖）

## FP-1.5-09 MCP（R19、R21）
- When 启动 `nexus mcp`，按 MCP 协议发送 initialize、tools/list、tools/call
- Then 列出工具 `nexus_ls`、`nexus_status`、`nexus_exec`、`nexus_session_ls`，各自带输入的 JSON Schema
- And 调用 `nexus_exec` 在 home 上执行命令，结果里有退出码和输出
- And 带凭据启动时，所有工具都以该 agent 的身份执行

## FP-1.5-10 所有查询和执行都有结构化输出（R19、R20）
- When 对每条查询和执行命令加 `--json`，标准输入关闭
- Then 标准输出是一份带 `schema` 字段的 JSON；出错时标准错误是一行带 `error` 字段的 JSON；没有任何命令等待输入

## FP-1.5-11 只看帮助就能用（R21）
- When `nexus --help` 和每条子命令的 `--help`
- Then 都成功，列出所有子命令和参数的说明；需要凭据的地方说明了 `--agent` 和 `NEXUS_AGENT`
